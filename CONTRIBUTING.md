# Как дополнять атлас через Git

Исторические данные хранятся в `content/`. Полный стандарт — [docs/CONTENT-SPEC.md](docs/CONTENT-SPEC.md), правила аргументации — [docs/EDITORIAL-POLICY.md](docs/EDITORIAL-POLICY.md).

1. Создайте ветку с названием по сути изменения.
2. Найдите существующие ID участников и источников. Новые записи создавайте по шаблонам в `templates/`.
3. Добавьте событие или дополните старое. Новые записи и содержательные изменения проверенных записей оформляйте со статусом `draft` до повторной проверки.
4. Для каждого нового ребра создайте отдельный файл в `content/relations/`. Укажите основание, источники и точные места в них, если они найдены.
5. Выполните `node --test tests/content.test.mjs` и `node scripts/build.mjs`. Команды работают без установки пакетов и сети; Node.js нужен только на этом этапе.
6. Проверьте изменения Markdown и двух производных файлов `dist/data.js`, `dist/knowledge.json`. Включите их в один коммит. Не редактируйте экспорт вручную.
7. Откройте pull request. Опишите добавленный факт или исправление, источники и имеющиеся сомнения. Синтаксис проверяет CI, исторические утверждения — рецензент.

В шаблонах намеренно есть незаполненные обязательные поля. Не копируйте их в рабочую базу без проверки. В каталоге `templates/` файлы сборщиком не читаются.

Критерий редакционной проверки: верная идентичность участников, корректный смысл даты, проверяемые основания фактов, явное отделение интерпретаций и рассмотрение известных возражений. Проверенный статус ставит рецензент после изучения источников, а не после успешного запуска тестов.

При переименовании отображаемого имени сохраняйте ID. При объединении дубликатов обновите ссылки и поясните замену в коммите. Изменения смысла существующего события описывайте явно; Git хранит историю прежних формулировок.

Для GitHub проверка уже описана в `.github/workflows/check-content.yml`. Для другой Git-платформы перенесите те же три команды: тесты, сборка, проверка отсутствия расхождений экспорта. Автоматическая публикация не настроена. Репозиторий и права доступа выбирает владелец проекта.
